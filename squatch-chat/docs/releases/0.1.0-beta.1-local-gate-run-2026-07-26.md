## Dependency-advisory review (follow-up, same date)

`npm audit` is currently broken against registry.npmjs.org for every npm
version tested (10.9.7, 10.9.8, 12.0.1): the bulk advisory endpoint returns a
gzip body **without** a `Content-Encoding` header, npm fails to parse it, and
its fallback (the retired quick-audit endpoint) returns 400. This also failed
CI run 30190042842 on commit `3aeb5ef`; the same step was green on `main` on
2026-07-14, confirming a registry-side regression, not a tree change.

Remediation applied after the gate run above:

- Added `scripts/audit-dependencies.mjs` (`npm run audit:deps`): queries the
  bulk advisory endpoint directly, transparently gunzips the malformed
  response, semver-matches every locked version, fails on high/critical in
  production dependencies. CI's "Audit production dependencies" step now runs
  it instead of `npm audit --audit-level=high`.
- Upgraded away all production high-severity advisories:
  - `next` 16.2.10 → 16.2.12 (4 high + 5 moderate advisories, incl. SSRF in
    Server Actions/rewrites, middleware bypass, DoS — GHSA range
    `>=16.0.0 <16.2.11`).
  - `postcss` override 8.5.16 → 8.5.23 (high, GHSA-r28c-9q8g-f849 — the old
    override pinned a vulnerable version).
  - new `sharp` override 0.35.3 (high, GHSA-f88m-g3jw-g9cj; Next's own range
    `^0.34.5` cannot reach the fix).
  - transitive `fast-uri` → 3.1.4, `js-yaml` → 4.3.0, `tar` → 7.5.22,
    root `brace-expansion` → 5.0.8, `minimatch`'s nested copy → 1.1.16.
- Post-remediation `npm run audit:deps`: **0 high/critical production
  findings** across 808 audited packages.
